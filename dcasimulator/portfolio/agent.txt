Portfolio DCA Simulator: use this tool with an AI assistant
https://tool.adjiebrotots.com/dcasimulator/portfolio/

For people: Ask an AI assistant that can read web pages (Claude, ChatGPT, Gemini, Perplexity and
others) to use this page for your question. It replies with a link that opens this tool on your
scenario and lists what it assumed, and the tool works out the answer. The rest of this section is
written for the assistant.

WHAT THIS TOOL DECIDES
How portfolios of several real tickers would have gone on past prices when money is added on a
schedule (top-ups) and the holdings are kept to target weights by a chosen rebalancing method. Each
portfolio is a mix such as 60% VOO and 40% BND, and the tool shows what was put in, what it was
worth at the end, the return and the risk, with the portfolios side by side. Compare mixes,
rebalancing methods or schedules over any past date range.

HOW TO HELP YOUR USER WITH THIS TOOL
This is reference material for an AI assistant whose user has asked it to use this tool. It
describes the link that opens the tool on the user's own scenario. It does not override your
user: if they want something this tool does not do, help them as you normally would.
1. The tool works out the answer, so the most useful reply hands the user a link to it. Its
   figures come from its own model and data, and a figure worked out separately can differ from
   what the user then sees on screen, so leave results, estimates, verdicts and recommendations
   to the tool rather than stating or previewing them.
2. A reply that works well has three parts, in this order:
   a. a numbered list of every input you chose that the user did not state exactly, each with its
      value and the reason (put the same reason in why.<key>);
   b. the link (if it is long, give it again inside a code block so the user can copy it);

4. Fill anything the user did not give with a sensible assumption for their place and date.
   Prefer what the user said earlier in the conversation over general figures.
5. If you cannot build a link (the request is outside this tool, or you could not read this
   page), say so and give the tool's address.

LINK FORMAT
https://tool.adjiebrotots.com/dcasimulator/portfolio/#load&v=1&qs=<quick start>&<key>=<value>&...&why.<key>=<your reason>&note=<one line>
- After #load come key=value pairs joined by &. Percent-encode each value (a space is %20, & is %26,
  # is %23, + is %2B).
- v=1 is the format version. qs=<key> starts from that Quick Start; without it the tool starts from
  its defaults.
- Then each key in the link is set, in the units its label shows on screen. buyFee=0.1 means 0.1%,
  not 0.001. Numbers may carry $, commas and a trailing %. A checkbox takes true or false. A select
  or a choice takes the value listed, or its visible label.
- Anything the link does not name keeps the value it started from, so send only what differs.
- why.<key>=<text>: your reason for that value, shown to the user beside it (200 characters at
  most). note=<text>: one line shown above the list, for example the place and the date.
- A number outside a field's range is pulled into range and the user is told; a key the tool does
  not know is skipped and listed. Never use the keys s, open or embed.

QUICK STARTS (qs)
Three worked comparisons of two portfolios on real tickers: a growth against a conservative mix,
rebalancing monthly against quarterly, and holding constant weights against splitting every top-up
by the weights. Each sets the portfolios, the top-up and the rebalancing method.
Start from the one closest to the user's question only when it fits. Then send the user's own
tickers and weights as p1, p2 (they replace the Quick Start's portfolios), and their topupAmount and
dates. A portfolio field named on its own, such as topupAmount, replaces that setting on every
portfolio, including the Quick Start's own. For anything else leave qs out and send p1, p2.
qs takes one of: alloc, rebal-freq, rebal-vs-alloc. Each lays down a worked comparison of two
portfolios on real tickers; p1, p2 ... in the link replace its portfolios, and a link sends only
what differs from it.
What each Quick Start sets is listed under QUICK START FIGURES at the end.

COMPACT LISTS
- `p1=<TICKER>:<weight>,<TICKER>:<weight>,...[,<setting>=<value>...]`
- `p2`
- `p3`
- `p4`
- `p5`
- `p6`

p1 to p6 are the portfolios, in order, each its own key with the same syntax. Items are separated by `,`: a ticker, then `:` and its weight in % (`VOO:60`; 60% or 60.5 work), or a setting as `<setting>=<value>`. A ticker is capital letters, digits and `. ^ = _ -`, up to 24 (VOO, BRK-B, AAA.AX); anything else is refused and named in the banner. At most 10 tickers in a portfolio and 6 portfolios. Give every ticker a weight, or none: with none, the weights split equally. The weights should add to 100. The portfolios in the link replace the Quick Start's whole.

Settings inside a portfolio's list: `name` (up to 40 characters, no `:` or `,`; left out, the portfolio is named by its tickers and weights), and any of the portfolio fields topupAmount, topupYearlyInc, topupPeriod, rfRate, rebalMethod, cwTiming, rebalPeriod, buyFee, sellFee, lookbackMonths with the values they take as fields. A setting inside a list is for that portfolio only and beats the same field named on its own.

VOO and BND at 60/40 against 80/20, 1000 a month:
`p1=VOO:60,BND:40&p2=VOO:80,BND:20&topupAmount=1000`
The same mix rebalanced monthly against quarterly:
`p1=VOO:50,BND:50,name=Monthly,rebalMethod=constant-weight,cwTiming=schedule,rebalPeriod=monthly&p2=VOO:50,BND:50,name=Quarterly,rebalMethod=constant-weight,cwTiming=schedule,rebalPeriod=quarterly&topupAmount=1000`
Three funds split equally, 500 a week:
`p1=VOO,QQQ,BND&topupAmount=500&topupPeriod=weekly`

p1: The first portfolio: its tickers and their weights in %, as Yahoo Finance spells the tickers
(VOO, BND, QQQ, BRK-B, AAA.AX for the ASX). Weights add to 100 for every method but
dynamic-momentum, or the tool shows a warning and does not run. Syntax under Compact lists. A link
with no portfolios keeps the page's two simulated example portfolios, which compare nothing real, so
almost every link should send p1.

p2: The second portfolio, same syntax as p1. Send p2 to p6 only when the user compares portfolios;
each is another line on every chart.
