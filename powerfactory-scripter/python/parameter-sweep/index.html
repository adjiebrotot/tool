Parameter sweeps in PowerFactory with Python: PV and QV curves

A parameter sweep sets one input to a series of values, reruns the calculation for each and records the results. The two classic sweeps are the PV curve (scale the load up until the load flow fails: the nose is the loadability limit) and the QV curve (hold a busbar at a voltage and read the reactive power it takes: the bottom is the reactive margin). On the Nine-bus example the nose is at 740 MW, 2.35 times the base load, and Bus 5's QV curve bottoms out at -257 Mvar.

What a parameter sweep is

A sweep answers "what happens as this changes?": loading against demand growth, losses against a tap position, a fault level against the number of units in service. The pattern is always the same: keep the original value, set the next one, run, check it converged, read, and put the original back at the end.

Voltage stability uses two sweeps:

  • PV curve: the voltage of a busbar against the power delivered, as the load (or a transfer) grows. The voltage falls slowly, then faster, until the load flow has no solution: the tip of the curve, the nose, is the maximum loadability. The distance from today's load to the nose is the loadability margin.
  • QV curve: the reactive power a fictitious condenser must inject to hold a busbar at each voltage. Where the curve bottoms out is the critical voltage; how far that bottom lies below zero is the reactive power margin of the busbar.

The method

  1. Keep the original values of everything the sweep changes, before the first step.
  2. Set the next value from the original, not from the previous step (multiplying the previous value compounds).
  3. Run and check: Execute() returns 0 when the load flow converged. For a PV curve the first failure is the end of the curve; for most sweeps it is a point to record and pass.
  4. Read what you sweep for: busbar voltages m:u, the delivered load m:P:bus1, a condenser's reactive power m:Q:bus1.
  5. Put everything back in a finally block, and delete any object the sweep made.

PV curve: scale every load to the nose

Each step multiplies the active and reactive power of the three loads by the same factor, so their power factor stays as it is. The extra power comes from the slack generator; generator reactive limits follow the study case (ignored in this example).

pv_curve.py

"""PV curve in PowerFactory with Python: scale every load up step by step until the load flow no
longer converges, recording the load busbar voltages on the way. The last point is the nose.

Runs on the "Nine-bus System" example project that comes with PowerFactory 2024.
"""
import csv
import sys

sys.path.append(r"C:\Program Files\DIgSILENT\PowerFactory 2024\Python\3.12")
import powerfactory

PROJECT = "Nine-bus System"
STUDY_CASE = "01- Load Flow"
WATCH = ["Bus 5", "Bus 6", "Bus 8"]            # the busbars of the three loads
STEP = 0.05                                    # load scaling step

app = powerfactory.GetApplicationExt()         # inside PowerFactory: powerfactory.GetApplication()
app.ActivateProject(PROJECT)
app.GetProjectFolder("study").GetContents(STUDY_CASE + ".IntCase")[0].Activate()

ldf = app.GetFromStudyCase("ComLdf")
loads = app.GetCalcRelevantObjects("*.ElmLod")
base = [(ld, ld.GetAttribute("plini"), ld.GetAttribute("qlini")) for ld in loads]
watch = [app.GetCalcRelevantObjects(name + ".ElmTerm")[0] for name in WATCH]

curve = []
scale = 1.0
try:
    while scale <= 5.0:
        for ld, p, q in base:                  # same power factor: P and Q scale together
            ld.SetAttribute("plini", p * scale)
            ld.SetAttribute("qlini", q * scale)
        if ldf.Execute() != 0:                 # no solution any more: past the nose
            break
        point = {"Scale": scale, "Load (MW)": sum(ld.GetAttribute("m:P:bus1") for ld in loads)}
        point.update({b.loc_name: b.GetAttribute("m:u") for b in watch})
        curve.append(point)
        scale = round(scale + STEP, 6)
finally:
    for ld, p, q in base:                      # put the loads back
        ld.SetAttribute("plini", p)
        ld.SetAttribute("qlini", q)

nose = curve[-1]
weakest = min(WATCH, key=lambda name: nose[name])
print(f"Nose: {nose['Load (MW)']:.0f} MW ({nose['Scale']:.2f} x the base load), "
      f"weakest busbar {weakest} at {nose[weakest]:.3f} p.u.")

with open("pv_curve.csv", "w", newline="") as f:
    out = csv.DictWriter(f, fieldnames=list(curve[0]))
    out.writeheader()
    out.writerows(curve)

QV curve: a fictitious condenser at Bus 5

A static generator with no active power, in voltage control, holds Bus 5 at each voltage from 1.10 p.u. down; the reactive power it injects is the curve. It is rated far above what it will need, so it never limits, and deleted at the end.

qv_curve.py

"""QV curve in PowerFactory with Python: hold one busbar at a set voltage with a fictitious
voltage-controlling static generator, step the voltage down and record the reactive power it
needs. The bottom of the curve is the reactive power margin of the busbar.

Runs on the "Nine-bus System" example project that comes with PowerFactory 2024.
"""
import csv
import sys

sys.path.append(r"C:\Program Files\DIgSILENT\PowerFactory 2024\Python\3.12")
import powerfactory

PROJECT = "Nine-bus System"
STUDY_CASE = "01- Load Flow"
BUS = "Bus 5"
VOLTAGES = [round(1.10 - 0.02 * k, 2) for k in range(36)]      # 1.10 p.u. down to 0.40 p.u.

app = powerfactory.GetApplicationExt()          # inside PowerFactory: powerfactory.GetApplication()
app.ActivateProject(PROJECT)
app.GetProjectFolder("study").GetContents(STUDY_CASE + ".IntCase")[0].Activate()

ldf = app.GetFromStudyCase("ComLdf")
bus = app.GetCalcRelevantObjects(BUS + ".ElmTerm")[0]
grid = bus.GetAttribute("cpGrid")                # the grid (ElmNet) the busbar belongs to

# The fictitious condenser: no active power, voltage control, rated well above what it will need.
cubicle = bus.CreateObject("StaCubic", "QV cubicle")
gen = grid.CreateObject("ElmGenstat", "QV condenser")
gen.SetAttribute("bus1", cubicle)
gen.SetAttribute("sgn", 2000.0)                  # MVA
gen.SetAttribute("pgini", 0.0)
gen.SetAttribute("av_mode", "constv")            # hold the voltage at usetp

curve = []
try:
    for v in VOLTAGES:
        gen.SetAttribute("usetp", v)
        if ldf.Execute() != 0:
            break
        curve.append({"Voltage (p.u.)": bus.GetAttribute("m:u"), "Q (Mvar)": gen.GetAttribute("m:Q:bus1")})
finally:
    app.ResetCalculation()                       # results first, then the objects can go
    gen.Delete()
    cubicle.Delete()

bottom = min(curve, key=lambda p: p["Q (Mvar)"])
if bottom is curve[-1]:
    print(f"{BUS}: Q still falls at {bottom['Voltage (p.u.)']:.2f} p.u.; extend VOLTAGES to find the bottom")
else:
    print(f"{BUS}: the curve bottoms out at {bottom['Q (Mvar)']:.0f} Mvar, at {bottom['Voltage (p.u.)']:.2f} p.u.")

with open("qv_curve.csv", "w", newline="") as f:
    out = csv.DictWriter(f, fieldnames=list(curve[0]))
    out.writeheader()
    out.writerows(curve)

How the script works

  • Step 2 is a "For a range of numbers" loop over the scaling factor, from LOAD_SCALING_FROM to LOAD_SCALING_TO in steps of LOAD_SCALING_STEP; it puts the loads back after every pass.
  • Step 3, Scale, sets plini and qlini of every load to the factor times its original value.
  • Step 4 runs the load flow. When it does not converge, "Stop the loop" ends the sweep with a message in the log: the nose.
  • Step 6 reads the lowest busbar voltage and where it is; step 7 adds the row.
  • After the loop, "Draw graph from results table" saves the PV curve as a PNG.

Pitfalls

  • The last converged point is an estimate of the nose. A load flow can also fail for numerical reasons. Use a smaller step near the end, or the continuation method, when the exact margin matters.
  • Scale P and Q together to keep each load's power factor; scaling only P sweeps the power factor too.
  • Where the extra power comes from shapes the curve. Here the slack takes it all. A transfer from one area to another, or generator reactive limits (iopt_lim on ComLdf), move the nose.
  • Voltage-dependent loads draw less as the voltage falls. Record the delivered power m:P:bus1, not the setpoint plini, on the x axis.
  • The QV condenser must never limit. Rate it well above the reactive power it will need, run without its limits, and delete it (after ResetCalculation()) when the sweep ends.
  • Put the inputs back from the stored originals in finally, so a stopped sweep never leaves the loads scaled.

Questions

What is a PV curve?

The voltage of a busbar plotted against the power delivered as load or transfer grows. Its tip, the nose, is the maximum loadability; beyond it the load flow has no solution.

What is a QV curve?

The reactive power a fictitious condenser must inject to hold a busbar at each voltage. The bottom of the curve marks the critical voltage, and its depth below zero is the reactive power margin.

How do I run a parameter sweep in PowerFactory with Python?

Store the original value, then for each step set it with SetAttribute, run the calculation, check that Execute() returned 0 and read the results. Put the original back in a finally block.

How do I scale all loads in PowerFactory with Python?

Loop over app.GetCalcRelevantObjects("*.ElmLod") and set plini and qlini to the factor times their original values. The load's scaling factor scale0 is another way.
