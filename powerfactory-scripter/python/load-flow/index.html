PowerFactory load flow with Python, and the results in CSV or Excel

In PowerFactory's Python API a load flow is one call: app.GetFromStudyCase("ComLdf").Execute(), which returns 0 when it converged. The results are then attributes: m:u for a busbar's voltage, c:loading for a line's loading. This page runs it on the Nine-bus example and saves every busbar and branch to CSV and Excel.

What a load flow gives you

A load flow (power flow) solves the steady state of the network for one operating point: the voltage magnitude and angle at every busbar, and from them the active and reactive power, current and loading of every line, transformer and generator. It is the base of almost every other study: contingency analysis repeats it per outage, hosting capacity repeats it per injection, a PV curve repeats it per load level.

In PowerFactory the load flow is a command object, ComLdf, stored in the study case. The study case decides what it solves: which grids are active, which operation scenario and which variations apply. Python only activates the case, sets the command's options, runs it and reads the answers.

The method

  1. Connect. powerfactory.GetApplicationExt() from your own Python (PowerFactory starts in the background), or powerfactory.GetApplication() inside a Python command in PowerFactory.
  2. Activate the project and the study case with app.ActivateProject(name) and the case's Activate().
  3. Get the load flow command with app.GetFromStudyCase("ComLdf") and set the options of this run: iopt_net (0 balanced AC, 1 unbalanced, 2 DC), iopt_lim (reactive power limits), iopt_at (automatic taps).
  4. Run it. Execute() returns 0 when the load flow converged. Anything else means there is no valid result to read.
  5. Read the results with GetAttribute: m:u, m:Ul and m:phiu on terminals (ElmTerm), c:loading, m:P:bus1 and c:Ploss on lines (ElmLne), with :bushv or :buslv on transformers.
  6. Save them as rows: the csv module for CSV, pandas for Excel. Put the command's options back so the study case stays as it was.

The script

This runs as it is on the Nine-bus System, one of the example projects that come with PowerFactory 2024. Change PROJECT and STUDY_CASE for your own.

load_flow.py

"""Load flow in PowerFactory with Python: run it, read every busbar and branch, save CSV and Excel.

Runs on the "Nine-bus System" example project that comes with PowerFactory 2024.
"""
import csv
import sys

sys.path.append(r"C:\Program Files\DIgSILENT\PowerFactory 2024\Python\3.12")
import powerfactory

PROJECT = "Nine-bus System"
STUDY_CASE = "01- Load Flow"

app = powerfactory.GetApplicationExt()         # inside PowerFactory: powerfactory.GetApplication()
app.ActivateProject(PROJECT)
app.GetProjectFolder("study").GetContents(STUDY_CASE + ".IntCase")[0].Activate()

# The study case's load flow command, with the options for this run (put back at the end).
ldf = app.GetFromStudyCase("ComLdf")
saved = {a: ldf.GetAttribute(a) for a in ("iopt_net", "iopt_lim", "iopt_at")}
ldf.SetAttribute("iopt_net", 0)     # 0 AC balanced, 1 AC unbalanced (3-phase), 2 DC
ldf.SetAttribute("iopt_lim", 1)     # 1 keeps generators within their reactive power limits
ldf.SetAttribute("iopt_at", 0)      # 1 lets transformer taps move automatically
try:
    if ldf.Execute() != 0:
        raise SystemExit("The load flow did not converge")

    buses = [{"Busbar": b.loc_name, "Nominal (kV)": round(b.uknom, 2),
              "Voltage (p.u.)": b.GetAttribute("m:u"), "Voltage (kV)": b.GetAttribute("m:Ul"),
              "Angle (deg)": b.GetAttribute("m:phiu")}
             for b in app.GetCalcRelevantObjects("*.ElmTerm")]

    branches = []
    for o in app.GetCalcRelevantObjects("*.ElmLne") + app.GetCalcRelevantObjects("*.ElmTr2"):
        end = "bus1" if o.GetClassName() == "ElmLne" else "bushv"   # the end P and Q are read at
        branches.append({"Branch": o.loc_name, "Class": o.GetClassName(),
                         "Loading (%)": o.GetAttribute("c:loading"),
                         "P (MW)": o.GetAttribute(f"m:P:{end}"), "Q (Mvar)": o.GetAttribute(f"m:Q:{end}"),
                         "Losses (MW)": o.GetAttribute("c:Ploss")})
finally:
    for a, v in saved.items():                  # leave the command as it was
        ldf.SetAttribute(a, v)


def save_csv(name, rows):
    with open(name, "w", newline="") as f:
        out = csv.DictWriter(f, fieldnames=list(rows[0]))
        out.writeheader()
        out.writerows(rows)


save_csv("load_flow_buses.csv", buses)
save_csv("load_flow_branches.csv", branches)

# Excel, one sheet per table: needs pandas and openpyxl (pip install pandas openpyxl).
try:
    import pandas as pd
    with pd.ExcelWriter("load_flow_results.xlsx") as xl:
        pd.DataFrame(buses).to_excel(xl, sheet_name="Busbars", index=False)
        pd.DataFrame(branches).to_excel(xl, sheet_name="Branches", index=False)
except ImportError:
    print("pandas is not installed: the CSV files are saved, the Excel file is not")

print(f"Saved {len(buses)} busbars and {len(branches)} branches")

How the script works

  • SETTINGS at the top are the only lines to edit: the project, the study case to start from, where the run folder goes, and TABLE_FORMAT ("csv", "xlsx" or "both").
  • Step 2 lists the study cases that match STUDY_CASE_PATTERN and activates each in turn (each_case).
  • Step 3, run_load_flow, runs the case's own ComLdf. When it does not converge, case_skipped keeps the row with the reason and the loop goes on to the next case.
  • Step 4 reads m:u of every busbar in service and energised, and keeps the lowest and highest with where they are.
  • Step 5 adds the row to the "Load flow" table, saved at the end as CSV or Excel in a new run folder, next to a run.log.
  • finish(app) puts back every value the workflow changed and the study case it started from.

Pitfalls

  • Check Execute() before reading. 0 means converged. After a failed load flow the m: and c: values are not a solution, yet GetAttribute still returns numbers.
  • Branch results need the end. m:P on a line raises AttributeError: write m:P:bus1 or m:P:bus2, and m:P:bushv or m:P:buslv on a 2-winding transformer. c:loading has no end.
  • Angles include transformer phase shifts. Bus 4 of the Nine-bus example reads 147.8 deg because generator transformer T1 shifts the angle by 150 deg. Compare angles on the same side of a transformer.
  • Changed options are saved in the project. SetAttribute on ComLdf changes the study case for good, so the script keeps the old values and puts them back in finally.
  • GetFromStudyCase makes what is missing. If the study case has no ComLdf, it silently creates one with default options. Check case.GetContents("*.ComLdf") when the options matter.
  • Excel needs pandas and openpyxl in the Python that runs the script. The CSV files need nothing beyond the standard library.

Questions

How do I run a load flow in PowerFactory with Python?

Activate the study case, then call app.GetFromStudyCase("ComLdf").Execute(). It returns 0 when the load flow converged.

How do I read busbar voltages after the load flow?

Loop over app.GetCalcRelevantObjects("*.ElmTerm") and read GetAttribute("m:u") for per unit, "m:Ul" for line-line kV and "m:phiu" for the angle in degrees.

How do I export PowerFactory load flow results to Excel?

Read the values into a list of dictionaries, then write it with pandas.DataFrame(rows).to_excel("results.xlsx") (pandas and openpyxl installed), or with the csv module for CSV.

What does iopt_net mean on ComLdf?

The network representation of the load flow: 0 balanced AC (positive sequence), 1 unbalanced three-phase AC, 2 DC load flow.
