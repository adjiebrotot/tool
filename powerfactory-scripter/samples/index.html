03

N-1 Line Contingency — Steady-State Assessment

▾
1 Objective

Determine whether removing any single line from service (an N-1 contingency) causes a bus voltage or line loading violation. This guide demonstrates how to configure the Custom scenario mode to model exactly the required contingencies — one row per N-1 event — and how to use wildcard output queries (*.ElmTerm, *.ElmLne) to capture voltage and loading across every element in the network with a single output variable definition.

2 Assumptions
  • 4-line network: Line_A.ElmLne, Line_B.ElmLne, Line_C.ElmLne, Line_D.ElmLne
  • Each N-1 contingency is one row in the scenario file — no combinatorial expansion
  • All bus voltages monitored via wildcard: *.ElmTerm → m:u
  • All line loadings monitored via wildcard: *.ElmLne → c:loading
  • Violations identified in post-processing: voltage outside 0.9–1.1 p.u. or loading > 100%
3 Initialisation & Input Variables

Select Custom as the Problem Type. In Custom mode the script reads each row of an Excel scenario file and applies those values once — no combinatorial expansion. This is the correct approach for N-1 analysis: you define precisely which line is out of service in each scenario, giving you exactly N + 1 runs (base case plus one outage per line).

Define one input variable per line, mapping each line to its outserv attribute. The Bounds and Step fields are not used in Custom mode — the actual values (0 or 1) come from the scenario file.

5 Output Variables

Using a wildcard object query (e.g. *.ElmTerm) tells PowerFactory to resolve all matching elements at runtime. When more than one object is matched, the tool writes one column per element in the output CSV, using the element's loc_name as the column header. No renaming or additional configuration is needed.

Two Scalar outputs cover the entire network: one for all bus voltages and one for all line loadings. Post-processing in pandas identifies any element outside acceptable limits.

To flag violations in pandas, identify bus and line columns then apply the relevant thresholds:

import pandas as pd

df = pd.read_csv("results.csv")

input_cols = ["Line_A_outserv", "Line_B_outserv", "Line_C_outserv", "Line_D_outserv"]
bus_cols  = [c for c in df.columns if c not in input_cols and c not in [...line_names...]]
line_cols = [c for c in df.columns if c not in input_cols and c not in bus_cols]

voltage_violation = ((df[bus_cols] < 0.9) | (df[bus_cols] > 1.1)).any(axis=1)
overload          = (df[line_cols] > 100.0).any(axis=1)

print(df[voltage_violation | overload])

Each row is a defined N-1 contingency — there is no need to filter for single-outage rows as there would be with a brute-force permutate approach.

Frequently Asked Questions

▾
How do I find the API Path? ▾

The API Path points to the PowerFactory Python API folder. It is located inside a Python subfolder of your PowerFactory installation, with a sub-folder for each available Python version. For example:

C:\Program Files\DIgSILENT\PowerFactory 2024\Python\3.10\

Choose the sub-folder that matches the Python version you are using to run your script.

When should I use Permutate? ▾

Enable Permutate on an input variable when you want the script to sweep that variable across all combinations with other permutated variables (full factorial / grid search). Disable it to vary the variable independently. For example, as a Bayesian optimisation parameter. Leave it unchecked for optimisation problems; the algorithm handles the search automatically.

Pro tip: Permutate works well for binary variables such as outserv (0 = in service, 1 = out of service). Be aware that permutating N lines produces 2N combinations — the base case, all N-1 outages, all N-2 outages, and so on. If you only need N-1 coverage, use Custom mode instead and define one scenario row per outage. This keeps the run count at N + 1 regardless of network size.
What does each Study Type do? ▾
Study Type PF Command Use to Analyse ...
Steady State Load Flow (ldf) Steady state voltages, currents, loading, etc
Dynamic RMS RMS simulation (rms) Fault response, generator dynamics, inverter dynamics, etc
Dynamic EMT EMT simulation (emt) Switching transients, power electronics, detailed waveforms, etc
Harmonic Harmonic load flow (hdf) Total harmonic distortion (THD), individual harmonics, etc
Python File vs. Notebook — which should I use? ▾

Python File (.py): Best for production use, scheduled runs, or when you want to import the script as a module. Run from the terminal or your IDE.

Notebook (.ipynb): Best for exploratory work, step-by-step debugging, or when you want inline plots and tables alongside the code. Open in Jupyter.
