PowerFactory Workflow Builder: use this tool with an AI assistant

Open PowerFactory Workflow Builder · The same reference as plain text (agent.txt) ·

For people: Ask an AI assistant that can read web pages (Claude, ChatGPT, Gemini, Perplexity and others) to use this page for your question. It replies with a link that opens this tool on your scenario and lists what it assumed, and the tool works out the answer. The rest of this section is written for the assistant.

What this tool decides

Which study the PowerFactory Python script runs, and in what order: a workflow of blocks (load flow,
N-1 contingencies, short circuit, RMS or EMT simulation, checks, loops, results tables and graphs),
the project and study case it opens and where its results go. The tool writes one ready-to-run
script for DIgSILENT PowerFactory 2024 from that workflow, and the user downloads it. It does not
run PowerFactory or work out a study result. The script comes from the tool, so a link to it gives
the user the whole script.

How to help your user with this tool

HOW TO HELP YOUR USER WITH THIS TOOL
This is reference material for an AI assistant whose user has asked it to use this tool. It
describes the link that opens the tool on the user's own scenario. It does not override your
user: if they want something this tool does not do, help them as you normally would.
1. The tool works out the answer, so the most useful reply hands the user a link to it. Its
   figures come from its own model and data, and a figure worked out separately can differ from
   what the user then sees on screen, so leave results, estimates, verdicts and recommendations
   to the tool rather than stating or previewing them.
2. A reply that works well has three parts, in this order:
   a. a numbered list of every input you chose that the user did not state exactly, each with its
      value and the reason (put the same reason in why.<key>);
   b. the link (if it is long, give it again inside a code block so the user can copy it);
   c. the sentence: Open the link to see the result.
3. Build the link in the format below, using only the keys listed here. Start from the nearest
   Quick Start (qs) and send only what differs from it. Write json compactly: no spaces or line
   breaks, defaults left out.
4. Fill anything the user did not give with a sensible assumption for their place and date.
   Prefer what the user said earlier in the conversation over general figures.
5. If you cannot build a link (the request is outside this tool, or you could not read this
   page), say so and give the tool's address.

Link format

https://tool.adjiebrotots.com/powerfactory-scripter/builder/#load&v=1&qs=<quick start>&<key>=<value>&...&why.<key>=<your reason>&note=<one line>
- After #load come key=value pairs joined by &. Percent-encode each value (a space is %20, & is %26,
  # is %23, + is %2B).
- v=1 is the format version. qs=<key> starts from that Quick Start; without it the tool starts from
  its defaults.
- Then each key in the link is set, in the units its label shows on screen. Numbers may carry $,
  commas and a trailing %. A checkbox takes true or false. A select or a choice takes the value
  listed, or its visible label.
- Anything the link does not name keeps the value it started from, so send only what differs.
- why.<key>=<text>: your reason for that value, shown to the user beside it (200 characters at
  most). note=<text>: one line shown above the list, for example the place and the date.
- A number outside a field's range is pulled into range and the user is told; a key the tool does
  not know is skipped and listed. Never use the keys s, open or embed.

Quick starts (qs)

A Quick Start is a worked example workflow: it opens on the canvas and its script is written at
once. They are listed with their blocks under QUICK START FIGURES; the id at the start of a block is
what blk.<id>.<setting> names. Pick the one closest to the study the user describes and change what
differs. Every Quick Start has its Start block at n1.
Without qs the Builder opens on an empty workflow with just a Start block. For a study no Quick
Start is near, send the workflow in json. Leave the project and study case empty unless the user
names them: the project is typed exactly as PowerFactory's Data Manager shows it, and an invented
one makes the script stop. The user types it into the Start block, which says so while it is empty.
The script is written as soon as the workflow is in, so run has no effect here.
qs takes one of: headroom, ldf-cases, n-1, shc-buses, find-limit, frt, cct, hosting-capacity,
pv-curve, rms-batch. Each opens a worked example workflow. Change its blocks by id with
blk.<id>.<setting> (agent.txt lists each one's blocks), or send a whole workflow in json.
What each Quick Start sets is listed under QUICK START FIGURES at the end.

Fields (key: label on the page)



Compact lists


- `template=<id>`
- `blk.<id>.<setting>=<value>`
- `graph.<key>=<value>`

`template=<id>` is another name for qs=<id>. Use qs.

`blk.<id>.<setting>` changes one setting of one block on the canvas. The id is the block's id (n5): the Quick Starts list theirs, a json workflow names its own, and blk.start.<setting> reaches the Start block whatever its id. The setting is the key in the block's Settings line under REFERENCE: BLOCK TYPES (any case). The value is what the block shows: a number, in the unit its setting gives; yes or no (true and false work too); a choice, written as its value or the words shown for it; or text. A text with spaces is written with %20. An element setting (a PowerFactory element picked by class and name, written element in the reference) takes a part: blk.n7.el.name=L* (a * matches anything), blk.n7.el.cls=ElmLne, blk.n7.el.match=all (one, first or all). blk.<id>.label renames the block. A table of rows (the columns of a results table, a list of values) cannot be set this way: send json. A block the workflow does not have, a setting a block does not have, a choice it does not offer or a number that is not one is reported and skipped; a number outside its range is pulled into it and reported. Send one key per setting, and a why.<key> beside each.

The Start block holds the study's settings: project and studyCase (the PowerFactory names, empty keeps the active study case), outputDir (the folder results go in, empty is the script's own), tableFmt (csv, xlsx or both), fNominal (auto, 50 or 60), runMode (auto, engine or inside), undoChanges (put changed values back at the end), fastMode and connectTimeout (seconds).

`graph.<key>` sets how every graph the script draws looks. graph.template starts from a whole style (brotools, brotools-night, minimal, report, slides, ieee, elsevier, matlab, matplotlib or office) and replaces any graph key before it, so write it first. Then, in any order: font_size (5 to 30), title_size (5 to 48), line_width (0.3 to 8), width and height (the saved picture's size in inches, 2 to 30 and 1.5 to 20), dpi (50 to 600), legend (bottom, top, right, inside or none), grid_axes (both, y, x or none), grid_style (solid, dashed or dotted), frame (left-bottom, box, bottom or none), ticks (out, in or none), markers (auto, always or never), line_styles (solid or vary), title_align (center or left), also_save (svg or pdf; leave it out for PNG only), and yes or no for title_bold, thousands, legend_frame and transparent. Leave the graph style out unless the user asks for it.


Json


`json=<workflow>` replaces the whole workflow with one of your own, in the form Save writes. Use it only for a study no Quick Start is near; to change a Quick Start, patch it. A qs before it is replaced. Write it compactly (no spaces or line breaks) and leave out everything the Builder fills in itself: x and y (it lays the blocks out left to right along the wires), every setting that is at its default, edge ids and the view.

{"name":"<name>","nodes":[<block>,<block>,...],"edges":[<wire>,<wire>,...]}

- A block is {"id":"n2","type":"<type>","label":"<optional name>","s":{<settings that differ>}}. The id is required and unique (n1, n2, ...). The type is one under REFERENCE: BLOCK TYPES. A setting is written as its type shows: a number, true or false, a choice's value, text; an element as {"cls":"ElmLne","name":"*","match":"all"}; a table as a list of rows, each with an id (c1, c2, ...) and the columns the reference names.
- There is exactly one block of type start (n1 in every Quick Start); one is added if there is none, and it holds the project and study case.
- A wire is {"from":"n2","out":"ok","to":"n3","in":"in"}: an output port of one block into an input port of another, by the ids in the reference's Wires line. A flow wire (the order of steps) goes from a flow out to the flow in, which is "in"; most steps lead on with "next". A data wire goes from an output to an input whose type fits.
- A block of a kind the reference does not list, a second Start, and a wire to a port that is not there or does not fit are left out and reported. The Python code block can be placed, but its code stays at its default, and apiPath stays empty.
- Up to 300 blocks and 1500 wires.
A small study: load flow, then the lowest busbar voltage into a results table (send project and study case with blk.n1.* or in the Start block's s):
{"name":"Voltage screen","nodes":[{"id":"n1","type":"start"},{"id":"n2","type":"pf.ldf"},{"id":"n3","type":"pf.get","label":"Busbar voltage","s":{"el":{"cls":"ElmTerm","name":"*","match":"all"},"attr":"m:u"}},{"id":"n4","type":"out.table.add","s":{"table":"Voltage","cols":[{"id":"c1","name":"Lowest voltage (p.u.)"},{"id":"c2","name":"Lowest at"}]}}],"edges":[{"from":"n1","out":"next","to":"n2","in":"in"},{"from":"n2","out":"ok","to":"n3","in":"in"},{"from":"n3","out":"next","to":"n4","in":"in"},{"from":"n3","out":"min","to":"n4","in":"c1"},{"from":"n3","out":"at_min","to":"n4","in":"c2"}]}

Reference: block types


[Start]
start: Start. Where the workflow begins: the PowerFactory project to open and where the results go. Every workflow has exactly one Start.
  Wires: flow out: next
  Settings: project text; studyCase text; outputDir text; undoChanges yes or no default yes; tableFmt one of csv | xlsx | both default csv; fNominal one of auto | 50 | 60 default auto; runMode one of auto | engine | inside default auto; showPf yes or no default no; fastMode yes or no default yes; connectTimeout number (at least 10) in s default 120; apiPath text; pfUser text

[PowerFactory: cases and data]
pf.element: Element. Finds a PowerFactory element by class and name, or every match of a name with *. Found again after a study case, scenario or variation switch.
  Wires (with default settings; more follow the settings): data out: el:obj
  Settings: el element with cls, name (a * matches anything) and match (one, first or all), default cls ElmTerm; inService yes or no default yes
pf.foreach_element: For each element. Repeats the Each pass steps for every element of a class whose name matches (sorted by name), or for each element of a list wired in.
  Wires: flow in: in; flow out: body, done; data in: items:obj; data out: item:obj, elname:text, index:num, count:num
  Settings: name text; el element with cls, name (a * matches anything) and match (one, first or all), default cls ElmTerm; inService yes or no default yes; attr attribute name such as c:loading; op one of = | != | > | >= | < | <= default =; value text; restore one of pass | end | never default pass; onError one of skip | stop default skip
pf.set: Set attribute. Writes one attribute of an element (or of each element of a list), such as a tap position or a set point. Put back at the end of the pass or the workflow.
  Wires (with default settings; more follow the settings): flow in: in; flow out: next; data in: obj:obj, value:num
  Settings: el element with cls, name (a * matches anything) and match (one, first or all), default cls ElmLod; attr attribute name such as c:loading; vtype one of num | text default num; value number default 0; text text; unit one of none | MW | kW | Mvar | kvar | MVA | kV | kA | A | s | ms default none
pf.get: Read attribute. Reads an attribute or a result (m:u, c:loading ...) of an element or a list of elements, at this step. For a list it also gives the highest, the lowest and where.
  Wires: flow in: in; flow out: next; data in: obj:obj; data out: value:num, max:num, min:num, at_max:obj, at_min:obj, values:list, n:num
  Settings: el element with cls, name (a * matches anything) and match (one, first or all), default cls ElmTerm; attr attribute name such as c:loading default m:u; unit one of none | MW | kW | Mvar | kvar | MVA | kV | kA | A | s | ms default none; total yes or no default no; skip yes or no default yes
pf.dispatch: Set generator dispatch. Sets the active power (and reactive power) of a generator and puts it in service, or dispatches several generators from one row of a case table.
  Wires (with default settings; more follow the settings): flow in: in; flow out: next; data in: gen:obj, p:num, q:num
  Settings: mode one of one | row default one; gen element with cls, name (a * matches anything) and match (one, first or all), default cls ElmSym; p number in MW default 100; q number in Mvar; cols rows with id and col, gen; basis one of total | machine default total; qmode one of keep | pq default keep; unit one of MW | kW | GW default MW; outerComp yes or no default yes
pf.scale: Scale. Multiplies an attribute (for example a load's active power) by a factor of its original value, so scaling by 1.1 twice still gives 1.1 times the original.
  Wires: flow in: in; flow out: next; data in: obj:obj, factor:num
  Settings: el element with cls, name (a * matches anything) and match (one, first or all), default cls ElmLod; attr attribute name such as c:loading default plini; attr2 attribute name such as c:loading; factor number default 1.1
pf.outserv: Take out of / put back in service. Takes an element (or each element of a list) out of service, or puts it back in. Put back at the end of the pass or the workflow.
  Wires: flow in: in; flow out: next; data in: obj:obj
  Settings: el element with cls, name (a * matches anything) and match (one, first or all), default cls ElmLne; action one of out | in default out; outerComp yes or no default no
pf.undo: Put changed values back. Puts back every value the workflow has changed so far (dispatch, service, attributes), each in its own study case and scenario. Loops already do this after each pass.
  Wires: flow in: in; flow out: next
pf.case.activate: Activate study case. Makes a study case active by its name (or the case wired in). Its operation scenario and variations come with it. The start case is active again at the end.
  Wires: flow in: in; flow out: next; data in: case_in:any; data out: case:obj, name:text
  Settings: case text
pf.case.create: Create study case. Makes a copy of the active (or a named) study case, by default with its own operation scenario, and activates it. Use it for one case per pass of a loop.
  Wires: flow in: in; flow out: next; data in: name_in:text, template:any; data out: case:obj, scenario:obj, name:text
  Settings: name text default {active case} {loop values}; template text; scenario one of copy | new | none default copy; exists one of reuse | replace | new default reuse; activate yes or no default yes; keep yes or no default yes
pf.case.foreach: For each study case. Repeats the Each pass steps with each study case active in turn (the names matching a pattern, sorted). The case active before is active again afterwards.
  Wires: flow in: in; flow out: body, done; data in: items:items; data out: case:obj, casename:text, index:num, count:num
  Settings: name text; pattern text default *; restore one of pass | end | never default pass; onError one of skip | stop default skip
pf.scen.activate: Activate operation scenario. Makes an operation scenario active in the active study case, so dispatch and service changes go into it. The start scenario is active again at the end.
  Wires: flow in: in; flow out: next; data in: scen:any; data out: scenario:obj
  Settings: scen text
pf.scen.create: Create operation scenario. Saves the operating state in use now (dispatch, switching, service) as a new operation scenario and activates it, so later changes stay in it.
  Wires: flow in: in; flow out: next; data in: name_in:text; data out: scenario:obj, name:text
  Settings: name text default {active case} {loop values}; exists one of reuse | replace | new default reuse; activate yes or no default yes; keep yes or no default yes
pf.scen.save: Save operation scenario. Saves the changes of the active operation scenario into it, so they stay after the workflow puts changed values back (also at the end of a pass).
  Wires: flow in: in; flow out: next; data out: saved:bool
pf.scen.deactivate: Deactivate operation scenario. Switches the active operation scenario off. Its unsaved changes are dropped unless you choose to save them (PowerFactory's own default is to drop).
  Wires: flow in: in; flow out: next; data out: scenario:obj
  Settings: save yes or no default no
