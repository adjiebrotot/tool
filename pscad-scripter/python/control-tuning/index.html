Tune a control in PSCAD by searching the gain

Tuning a control against an EMT model is a loop: change a gain, disturb the system, run, and measure how the response came back. Doing it by eye off a graph is slow and inconsistent, and the thing being judged, how well damped a ringdown is, is exactly the kind of number a script measures better than a person. This page is how to get that number, and how to let a search use it.

What a tuning run measures

A control is judged on how it answers a disturbance. In an EMT model the disturbance is a component you already have: a short fault, a step on a set point, a switched load. What comes back is a waveform, and the tuning question is what shape that waveform has.

What is readWhat it says
Damping ratioA ringdown fitted through its envelope peaks. Above about 0.05 is usually called well damped; a negative ratio means the oscillation is growing.
OvershootHow far past the final value the first swing goes, as a fraction of the step. A control that is too fast overshoots.
Rise timeHow long the response takes to cross from near the start to near the end. A control that is too slow has a long one.
Settling timeHow long until the response stays inside a band around its final value. The number a specification usually quotes.
Final valueWhere it ended up. A steady state error says the control is not holding its set point.

The one that decides most tuning arguments is the damping ratio. It is fitted from the envelope of the ringdown: take the successive peaks, fit the exponential they decay along, and the ratio falls out of the rate of that decay against the oscillation's own frequency. Two things about it are worth saying plainly.

  • A negative ratio is a real answer, not an error. It means the peaks are growing: the oscillation is unstable. A tuning script that treats a negative ratio as a failed measurement will hide the one result that matters most.
  • A flat signal has no ratio at all. If the disturbance did not excite anything, there are no peaks to fit, and the honest output is "no ringdown", not a damping ratio of zero. Zero means marginally stable, which is a very different statement.

The method

One tuning run

  1. Write the gain on the control component.
  2. Disturb the system at a time well after the case has settled. A short fault is the usual choice because it excites everything; a set point step is cleaner when you only want one loop's response.
  3. Run long enough for the ringdown to decay, or to clearly fail to. Ten seconds is a common choice for an electromechanical mode.
  4. Read the channel the mode shows up in: machine speed for an electromechanical oscillation, a terminal voltage for an exciter, a power flow for a damping controller.
  5. Fit the damping, and read overshoot and settling time from the same waveform.
  6. Record the row, and put the gain back.
mark = px_mark()
px_set(exciter, "KA", gain)

set_fault(app, "master:tpflt", at=1.0, duration=0.05)     # a short kick
run = px_run(app, duration=10.0, step=50, plot_step=250)

speed = run.series("Machine Speed")
d = damping(speed, after=1.1)        # .ratio, .frequency, .stable, .why
o = overshoot(speed, after=1.1)      # .overshoot, .rise_time, .settling_time

table("Damping").add({
    "Gain": gain,
    "Damping ratio": d.ratio,
    "Mode (Hz)": d.frequency,
    "Overshoot": o.overshoot,
    "Settling (s)": o.settling_time,
})
px_undo(mark)

Letting a search pick the gain

Once a single run gives a number, a search can drive it. Two kinds are worth knowing apart.

  • Optimise looks for the gain that gives the best number: the highest damping ratio, or the shortest settling time. It is the right tool when every candidate is acceptable and you want the best of them.
  • Find limit looks for the boundary: the largest gain that is still stable, the smallest that still meets a settling time. It is the right tool when the answer is a limit rather than an optimum, and it is much cheaper, because bisection halves the bracket every try.
# Optimise: each try gets a gain, runs, and reports one number back.
def attempt(gain):
    mark = px_mark()
    px_set(exciter, "KA", gain)
    run = px_run(app, duration=10.0, step=50, plot_step=250)
    d = damping(run.series("Machine Speed"), after=1.1)
    px_undo(mark)
    return d.ratio if d.ratio is not None else -1.0    # no ringdown is not a win

Give the search a bracket you believe in. An EMT run per try is expensive, so the range matters more here than it would on an algebraic model, and a search told to look between 1 and 10,000 will spend most of its tries in places no engineer would.

Tuning more than one gain

Two gains make a surface rather than a curve, and the number of runs goes up fast. A grid is honest and slow; a search that chooses where to look next is faster and needs a sensible starting point. Either way, the results table holds one row per try with both gains on it, so the surface can be drawn afterwards without re-running anything.

How the script works

  • The disturbance is a 50 ms fault at 1 s: short enough to be a kick rather than a study in its own right, late enough that the case has settled.
  • The run is 10 seconds, so an electromechanical mode has room to decay or clearly not to.
  • The Damping of a ringdown block fits the envelope peaks after the disturbance and gives back the ratio, the mode frequency and whether it calls it stable.
  • A negative ratio comes through as a negative number and reads as not stable, rather than being clamped or treated as an error.
  • A flat signal gives no ratio at all, with a reason, so a disturbance that did not excite the mode is visible instead of being recorded as perfect damping.
  • The Pass / fail block turns the ratio into a verdict, which is what a Find limit search needs each try to report.

Pitfalls

  • Measuring from before the disturbance. The fit has to start after the kick, or the settled part before it flattens the envelope and the ratio comes out too high.
  • A run that ends while it is still ringing. A fit over two peaks is not a fit. If the ratio moves a lot when the run gets longer, the run was too short.
  • Treating a negative damping ratio as an error. It is the answer: the oscillation is growing. Record it and let the verdict fail.
  • Treating "no ringdown" as perfect damping. A disturbance that excited nothing produces no peaks. That is a flaw in the test, not a well tuned control.
  • Reading the wrong channel. A mode that does not appear in the channel you recorded cannot be measured. Record the quantity the mode actually moves.
  • A search with no run budget. Every try is a full EMT run. Bound the number of tries, and prefer Find limit over Optimise when the answer is a boundary.
  • Leaving the last gain written. The gain a search tried last is not the gain it recommends, and it is written in the case. Undo each try, and write the chosen value deliberately at the end.

Questions

How do I measure damping in PSCAD?

Disturb the system, run long enough for the oscillation to decay, and fit the envelope through the successive peaks of the recorded channel. The damping ratio comes from the rate of that decay against the oscillation’s own frequency. A negative ratio means the peaks are growing.

What damping ratio is good enough?

It depends on the grid code or the study brief, but around 0.05 is a common threshold for calling an electromechanical mode well damped. What matters more for a script is being consistent: fit it the same way, from the same channel, over the same window, every run.

Should I use Optimise or Find limit to tune a gain?

Optimise when you want the best value of a number, such as the highest damping ratio. Find limit when the answer is a boundary, such as the largest gain that is still stable: bisection halves the bracket every try, which matters when each try is a full EMT run.

What disturbance should I use for a tuning run?

A short fault excites everything and is easy to repeat, which suits finding modes. A step on a set point is cleaner when you want one loop’s response and nothing else. Either way, apply it well after the case has settled.
