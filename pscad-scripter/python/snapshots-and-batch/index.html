PSCAD snapshots and running cases in a batch

An EMT case starts from zero every time and spends the first second or two getting to a steady state that is the same on every run of a study. Two things get that time back. A snapshot runs the initialisation once and starts every later run from the state it saved. A simulation set runs several cases at the same time instead of one after another. Together they turn an overnight sweep into a lunch break.

What a snapshot is

A snapshot is the whole state of the simulation at one instant, written to a file beside the case. Every capacitor voltage, every inductor current, every controller state. A later run told to start from it begins in that state instead of from zero, so the initialisation does not happen again.

For a study that varies something after the case has settled, which is most of them, that is the whole initialisation removed from every pass but the first. A case that takes 2 s to settle and 2 s to show the event goes from 4 s of simulation per pass to 2 s: half the work, over twenty passes or two hundred.

It only works when the thing being varied happens after the snapshot. A sweep over fault durations qualifies, because the case is the same until the fault. A sweep over a transformer rating does not: that changes the steady state the snapshot captured, so the snapshot is wrong for every value but the one it was taken with.

And a simulation set

A simulation set is a list of cases PSCAD runs as a group, and a volley is how many of them run at the same time. Each task in the set can override the duration and the time steps, so one set can hold the same case under several conditions. This is the parallelism PSCAD has: not one case split across cores, but several cases running side by side.

Snapshots, then simulation sets

Taking a snapshot

The snapshot is taken at a time, during a run. Tell the case when to take it, run past that time, and the file is written.

snapshot_at(app, 2.0, name="settled")          # take it at t = 2 s
px_run(app, duration=2.2, step=50, plot_step=250)   # run past it, once

Starting from it

A run told to start from a snapshot begins at the time the snapshot was taken, not at zero. Times inside the run are still absolute, so a fault at 0.1 s after a snapshot taken at 2 s is written as 2.1 s unless the case is set to restart the clock.

snapshot_use(app, "settled")

for duration in (0.08, 0.12, 0.16, 0.20):
    mark = px_mark()
    set_fault(app, "master:tpflt", at=2.1, duration=duration)
    run = px_run(app, duration=2.0, step=50, plot_step=250)
    table("Snapshot").add({
        "Fault (s)": duration,
        "Lowest voltage": peak(run.series("Vbus"), kind="min").value,
    })
    px_undo(mark)

snapshot_off(app)      # later runs start from zero again

Put the case back to starting from zero when the script ends. A case left set to start from a snapshot will quietly use it the next time anyone opens it, including for a study the snapshot does not suit.

Running several cases at once

A simulation set holds tasks, each one a case, and the volley says how many run together. Four at a time on a four core machine is the usual starting point; more than the machine has cores makes everything slower.

sim = simset_create(app, "PXB_batch", volley=4)
simset_add(sim, ["caseA", "caseB", "caseC", "caseD"])
simset_override(sim, duration=5.0, step=50)       # the same settings for every task

result = simset_run(sim)
for task in result.tasks:
    table("Batch").add({"Case": task.name, "Status": task.status, "Seconds": task.seconds})

On PSCAD 5.0.0 the Automation Library has add_tasks but not add_task: add them as a list. The generated scripts do this for you.

Which one to reach for

  • Same case, something varied after it settles: a snapshot. The saving is the initialisation, every pass.
  • Different cases, or variations that change the steady state: a simulation set. The saving is wall clock time, not simulated time.
  • Both: take a snapshot per case, then run the cases as a set. The two do not get in each other's way.

                # -- Step 7: Run simulation (2 s, 50 us step) --
                run = px_run(app, 2, 50, 250, None, events=[(0.1, "Fault")], build="auto", read="out", keep_files=False)

                    continue

                    continue

                raise

                case_failed(err)

How the script works

  • Save a snapshot sets the time the snapshot is taken; the Initialise run that follows is the one run that pays for the initialisation.
  • Start from a snapshot comes before the loop, so every pass of the loop begins at the settled state rather than at zero.
  • The fault time inside the loop is absolute: it is after the snapshot time, not relative to it.
  • The loop body is the same three blocks as any other sweep, which is the point: the snapshot changes what a run starts from and nothing else.
  • Start from zero again is wired at the end, so the case is not left set to a snapshot that the next study would not want.
  • The Builder warns when a block changes the model between the snapshot and the run that uses it, because that change is not in the saved state.

Pitfalls

  • A snapshot taken before the case has settled. Every later run then starts from a transient, and the results are repeatable and wrong. Check the snapshot time against the waveform before trusting it.
  • Changing the model after the snapshot and expecting the change to be in it. The snapshot holds the state as it was. A parameter written afterwards applies from the restart, which is usually what you want for a fault and never what you want for an impedance.
  • Times measured from the restart. The clock does not reset by default: a fault 100 ms after a snapshot taken at 2 s is at 2.1 s.
  • Leaving the case set to start from a snapshot. It is a case setting, not a session one, so it survives the script and the next person to open the case.
  • A volley larger than the machine. Every task is a full EMTDC process. More tasks than cores means they take turns, and the whole set finishes later than a smaller volley would.
  • Several tasks building in the same folder. Each build writes beside the .pscx. Give each task its own copy of the case, or let the set build them in turn before the volley starts.

Questions

What is a PSCAD snapshot?

A file holding the entire state of the simulation at one instant: every capacitor voltage, inductor current and controller state. A run told to start from it begins in that state instead of from zero, which removes the initialisation from every run of a study after the first.

When is a snapshot not safe to use?

When the thing being varied changes the steady state the snapshot captured. Sweeping a fault duration is fine, because the case is identical until the fault. Sweeping a transformer rating or a source impedance is not: the snapshot holds the state of a different network.

How do I run several PSCAD cases at once?

Put them in a simulation set and give the set a volley. The volley is how many tasks run at the same time; each task is a full EMTDC process, so a volley of about the number of cores on the machine is the practical limit.

Does a snapshot make the simulation faster?

It removes simulated time, not solver work per step. A case that takes 2 s to settle and 2 s to show the event runs half as long per pass once the settling is snapshotted, and the saving multiplies by the number of passes.
