Fault ride through and critical clearing time in PSCAD with Python

A fault study in PSCAD is a loop around a fault that is already drawn in the case: the script writes when it starts and how long it lasts, runs the case, and reads how the voltage dipped and the machines swung. Do that over a range of durations and it is a fault ride through study; halve the gap between a duration that passes and one that fails and it is a critical clearing time.

How a fault is applied from a script

PSCAD has no event list. A fault is the Three Phase Fault component (master:tpflt) drawn at the point to be faulted, and it decides which phases are faulted and through what resistance. When it is applied comes from the logic wired into it, usually a Timed Fault Logic block (master:tfaultn), which holds the start time TF and the duration DF.

So a script times a fault by writing those two parameters, and the Three Phase Fault itself has nothing to time: in PSCAD 5.0.0 it has no time parameters at all. That is the one thing most first fault scripts get wrong.

flt = project.find_all("master:tfaultn")[0]
flt.parameters(TF="1.0 [s]", DF="0.12 [s]")      # on at 1 s, cleared at 1.12 s

fault = project.find_all("master:tpflt")[0]
fault.parameters(A="YES", B="YES", C="YES", G="YES", RON="0.01 [ohm]")   # what is faulted

The method

  1. Let the case settle first. Put the fault well after the start-up transients have died away, and run long enough after it for the machines and controls to show whether they recover.
  2. Loop over the durations to test, or search for the longest one that passes.
  3. Each pass: write TF and DF, run, read the channels.
  4. Check and record: the lowest voltage, the speed nadir or the highest speed, whether the case rode through.
  5. Put the fault back after each pass, so the next one starts from the case as it was.

Fault ride through over durations

for duration in num_range(0.08, 0.24, 0.04):
    mark = px_mark()
    set_fault(app, "master:tfaultn", "", at=1.0, duration=duration)
    run = px_run(app, duration=5, step=50, plot_step=250)
    v = run.series("Vpcc")
    table("FRT").add({"Fault duration (s)": duration,
                      "Lowest voltage": peak(v, kind="min").value})
    px_undo(mark)

set_fault writes the start and duration on whatever fault component it is given, by the parameter names PSCAD uses for them, and gives back the start and clearing times so the checks and the graphs know where the event was. Given a component with no timing parameters, such as the Three Phase Fault, it stops and lists the parameters that component does have.

The critical clearing time by bisection

A critical clearing time is the longest fault the case survives. Rather than sweep thirty durations, try the two ends, then keep halving the gap between the longest that passed and the shortest that failed. From 0.05 s to 0.5 s that is about eight runs to 5 ms.

def one_try(duration):
    trial = Trial({"Fault duration (s)": duration}, "min")
    mark = px_mark()
    try:
        set_fault(app, "master:tfaultn", "", at=1.0, duration=duration)
        run = px_run(app, duration=5, step=50, plot_step=250)
        highest = peak(run.series("Machine Speed"), kind="max").value
        trial.report(ok=highest <= 1.05)          # stays in step
    finally:
        px_undo(mark)
    return trial

cct = find_limit(one_try, 0.05, 0.5, 0.005, passes="low")
print(cct.limit, cct.status)                      # the last duration that passed

What counts as staying in step is the study's own decision: a speed band, a rotor angle, a voltage that comes back within a time. Make the test the one your connection requirement states.

How the script works

  • The loop is num_range(0.08, 0.24, 0.04), both ends included. Each pass opens a mark and puts every parameter back in the finally, so a pass never inherits the previous one's fault.
  • set_fault(app, "master:tfaultn", ...) writes the duration of this pass on the Timed Fault Logic. The event it returns goes to px_run so the checks know the fault time and the graph marks it.
  • A pass that does not build or stops early is skipped with a note in the table, rather than ending the study.
  • peak(voltage, kind="min") is the voltage dip; nadir(speed, ...) the speed nadir, with whether it turned around.
  • collect_series keeps each pass's speed curve and draw_collected draws them on one graph at the end, one line per duration.

Pitfalls

  • Writing the time on the Three Phase Fault. It has no time parameters; the time is on the Timed Fault Logic wired to it. The Builder's Set a fault block names master:tfaultn for that reason.
  • A fault during the start-up. A case starts from zero and needs time to reach its steady state. A fault at 0.1 s tests the initialisation, not the plant. Look at a run with no fault first and put the fault after it has settled, or start from a snapshot.
  • Speed in per unit, a limit in hertz. A machine speed channel is usually per unit, so a stay-in-step test of 1.05 is 5 % over speed, not 1.05 Hz. Check the unit the channel carries (series.unit).
  • A search that stops early. A try that gives no answer (a run that did not build, a check with no data) ends a bisection with status UNKNOWN by default. Read the status, not only the limit.
  • The case changed after the study. Every write is in the case. Keep the mark and undo around each pass, and UNDO_CHANGES = True for the run as a whole.

Questions

How do I apply a fault in PSCAD from Python?

Write the start time and the duration on the timing logic that drives the fault, usually Timed Fault Logic (master:tfaultn, parameters TF and DF), then run the case. The Three Phase Fault component sets which phases are faulted and the fault resistance.

How do I find the critical clearing time in PSCAD?

Run the case with a fault of a given duration and test whether it stays stable, then halve the gap between the longest duration that passed and the shortest that failed until it is narrow enough. That takes about eight runs instead of a sweep of thirty.

Why does my fault not change between runs?

Most often the time is being written on a component that does not use it, or the parameter is written without its unit. Read the value back after writing it, and write the time on the Timed Fault Logic.
