Sweep a parameter in PSCAD and collect the results

A sweep is the first thing worth automating in PSCAD, because an EMT run takes as long as it takes and a sweep of them is an afternoon of starting the next one by hand. The script is short: write the parameter, build, run, read a channel, take a number off it, record the row, put the parameter back. What makes it worth getting right is the last step, and the units.

What a sweep changes

A PSCAD sweep writes one parameter on one component before each run. The parameter is named exactly as the component's dialog names it, and the component reference lists every one with its unit, range and default: R on a resistor, Tmva on a transformer, Es on a source.

Two things about PSCAD values are worth knowing before the first sweep.

  • A value carries its unit in its text. A resistance reads back as 2.5 [ohm], not as 2.5. PSCAD keeps the unit that was written rather than normalising it, so a value written as 2500 [mohm] stays in milliohms and reads back that way. Write the unit you mean.
  • A written value is written in the case, not in a session. There is no read-only mode: the last value of a sweep becomes the case's new setting unless the script puts it back.

PSCAD also has its own Multiple Run component, which runs the case once per combination without the script restarting it. It is faster for a small self-contained sweep. A script loop is easier to read, easier to check, and the only option once the sweep has to change several things or decide what to try next, so these guides use the loop.

The method

  1. Find the component once, before the loop. Finding it every pass is wasted time and hides a model that has two of them.
  2. Open a mark at the top of each pass so the pass can be undone at the bottom.
  3. Write the parameter, in the unit it already carries.
  4. Run. PSCAD builds the case again by itself when the change needs it.
  5. Read the channel the study cares about, and take one number off it.
  6. Add a row. The loop value is added for you, so the table always says which pass a row came from.
  7. Undo the mark, so the next pass starts from the case as it was.
load = px_find(app, "master:resistor", "Load")       # once, before the loop

for value in num_range(1.0, 10.0, 1.0):
    mark = px_mark()
    px_set(load, "R", value, unit="ohm")

    run = px_run(app, duration=1.0, step=50, plot_step=250)
    v = run.series("Vbus")
    worst = peak(v, kind="abs")

    table("Sweep").add({
        "R (ohm)": value,
        "Peak voltage": worst.value,
        "At (s)": worst.time,
    })
    px_undo(mark)

Sweeping two things at once

Nest the loops. The results table records both loop values on every row, so a two dimensional sweep comes out as a long table that pivots into a surface rather than as a grid you have to reassemble.

for r in num_range(1.0, 10.0, 1.0):
    for mva in (100, 200, 400):
        mark = px_mark()
        px_set(load, "R", r, unit="ohm")
        px_set(source, "MVA", mva, unit="MVA")
        run = px_run(app)
        table("Sweep").add({"Peak": peak(run.series("Vbus"), kind="abs").value})
        px_undo(mark)

Sweeping something that is not a number

A Choice parameter takes a symbolic value, not the label the dialog shows. The component reference lists both for every Choice, so a sweep over winding connections writes YD1="Y" and YD1="D" rather than the words beside them.

for connection in ("Y", "D"):
    px_set(xfmr, "YD1", connection)

What the table is for

One row per pass, every loop value on the row, and the numbers the checks produced. It is saved as CSV or Excel into the run folder when the script ends, so the sweep leaves something that can be plotted, diffed against the last model, and attached to a report without being retyped.

How the script works

  • The Component block finds the component once and hands it to the Set parameter block, so it is found before the loop rather than inside it.
  • The For a range of numbers block is the sweep. Its value output goes into Set parameter, so the range is in one place.
  • px_set records the old value as it writes, which is what makes the undo at the end of the pass cheap and exact.
  • Every pass is wrapped in px_mark() and px_undo(mark), so the parameter goes back before the next value is written and the case ends as it started.
  • The Add row block writes the loop value as well as the check, so the table says which pass each row came from without being told.
  • Draw graph from results table plots the collected column against the swept one after the loop, which is the picture a sweep is usually for.

Pitfalls

  • Dropping the unit. px_set(obj, "R", 2.5) writes 2.5 in whatever unit the parameter already carries. If that is milliohms, the sweep is a thousand times off and nothing complains. Name the unit.
  • Not putting the value back. A PSCAD parameter a script writes is written in the case. Without the undo, the case on disk ends up holding the last value of the sweep.
  • Finding the component inside the loop. It costs a search per pass and, worse, it hides the case where two components match: the script quietly works on whichever came first.
  • A range that steps past its end. Floating point means a range from 0.1 to 0.5 in steps of 0.1 may give four values or five. Where the end point matters, list the values instead.
  • Sweeping something that needs a rebuild and not allowing for the time. Some parameters are used when the Fortran is generated, so writing them costs a build per pass. The first pass of a sweep will tell you which kind you have.
  • Reading a channel the case does not record. The sweep runs to the end and the column is empty. Run once with run.names() printed, and copy the titles from there.

Questions

How do I sweep a parameter in PSCAD with Python?

Find the component once, then loop: write the parameter with its unit, run the case, read the channel you care about, take a number off it and add a row. Put the parameter back at the end of each pass, because a value a script writes is written in the case itself.

Should I use the Multiple Run component or a Python loop?

The Multiple Run component is faster for a small, self-contained sweep because PSCAD does not restart the case between runs. A Python loop is easier to read and check, and it is the only option once the sweep changes several things, reads results between passes, or decides what to try next.

How do I write a value with its unit in PSCAD?

Write it as text with the unit in brackets: "250 [MVA]", "2.5 [ohm]". PSCAD keeps the unit you wrote rather than converting it, so a value written in milliohms stays in milliohms and reads back that way.

How do I sweep a dropdown parameter?

A Choice parameter is written with its symbolic value rather than the label shown in the dialog. The component reference lists the symbolic value beside the label for every Choice in the Master Library.
