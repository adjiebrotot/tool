How to automate PSCAD studies with Python

PSCAD is automated through its Automation Library, the Python package mhi.pscad. A script opens a case, writes the parameters of the components already drawn in it, builds the case into Fortran, runs the EMT simulation, and reads the waveforms the run recorded. Every study on this page is that same loop with a different thing varied and a different number taken off the waveform. Each guide opens the same study in the Workflow Builder, which writes the Python for you from blocks.

The pattern every PSCAD automation follows

PSCAD has one calculation: build the case and run it in the time domain. There is no load flow to call, no short-circuit command and no frequency-domain harmonic scan, so every study is a loop of runs over something changed in the model, with the answer read out of the recorded waveform afterwards.

import mhi.pscad

pscad = mhi.pscad.connect()                   # or launch()
project = pscad.project("mycase")

fault = project.find_all("master:tfaultn")[0]
before = fault.parameters()                   # so it can be put back

rows = []
try:
    for duration in (0.08, 0.12, 0.16, 0.20):
        fault.parameters(DF=duration)         # 1. change the model
        project.build()                       # 2. Fortran, every time it changed
        project.run()                         # 3. the time domain run
        v = read_channel(project, "Vpcc")     # 4. read the recorded waveform
        rows.append({"Fault (s)": duration,   # 5. take the number off it
                     "Lowest voltage": min(v)})
finally:
    fault.parameters(**before)                # 6. leave the case as you found it
  1. Connect: mhi.pscad.connect() for the PSCAD that is open, launch() to start one, application() from inside PSCAD.
  2. Change the model, because there is no event list: a fault, a trip or a set-point change is a component already in the case, and a study writes its parameters.
  3. Build: the case is Fortran, and it has to be compiled again after anything that changes the generated code.
  4. Run: duration in seconds, the solution step and the plot step in microseconds.
  5. Read the channels: the output channels in the case are written ten to a .out file with a .inf index naming them.
  6. Check and record: an RMS, a THD, a nadir or a damping ratio, worked out from the waveform and written into a table.
  7. Put everything back, because a parameter a script writes is written in the case, not in a session.

Write it, or have it written

What is worth automating first

  • Anything that is the same run many times over: every fault duration, every value of a parameter, every network arrangement.
  • Runs that take long enough to be worth not watching: an EMT run takes as long as it takes, and a sweep of them is an afternoon of starting the next one by hand.
  • Searches: a critical clearing time or the gain that just settles, found by bisection in a handful of runs rather than a grid of them.
  • The reading of the waveform: an RMS, a THD or a damping ratio worked out the same way every time, instead of by eye off a graph.

Questions

Can PSCAD be automated with Python?

Yes. PSCAD has an automation server, and the Automation Library (pip install mhi-pscad) is the Python package that drives it: open a workspace and a project, read and write any component's parameters, build, run, and read the results the run recorded.

Can I run a load flow or a short circuit in PSCAD from Python?

No, and not from the interface either. PSCAD is an electromagnetic transient simulator: the only calculation is a time-domain run. A fault level comes out of applying a fault and reading the current; a steady state comes out of running until the case settles.

Why does a PSCAD case have to be built before it runs?

A PSCAD case is compiled into Fortran and linked into an executable that EMTDC runs. Anything that changes the generated code, including most parameter changes, needs the case built again, and a build error is a compiler error with a line in the generated source.

Do I need to know Python?

Not for the studies the Workflow Builder covers: it writes the script from blocks. Reading the file it writes is a good way to learn the Automation Library.
