How a PSCAD parameter is named, written and read

A definition name
Always namespaced: master:tpflt, never tpflt. Project.find_all() matches it exactly, with no wildcards, so a bare name or a pattern comes back empty.
A value and its unit
Written together as text: "250 [MVA]", "2.5 [ohm]". PSCAD stores the unit you wrote rather than normalising it.
Reading a value back
A unit-carrying value is a subclass of float and its unit lives only in its text, so read it as text before you read it as a number.
Type
Real, Integer, Text, Choice, Boolean or Table, as PSCAD reports it. A Choice is written with its symbolic value, which this reference lists beside the label.
Range and default
As the component dialog gives them. A range of 0 to 0 means the dialog sets none, not that the value must be zero.
A condition
Some parameters only matter while another is set a certain way. The reference shows the condition PSCAD itself carries.

Read and write any component

import mhi.pscad

pscad = mhi.pscad.connect()                # launch() starts a new PSCAD instead
project = pscad.project("mycase")

for comp in project.find_all("master:tpflt"):        # the definition, exactly
    print(comp.name, comp.parameters())

fault = project.find_all("master:tfaultn")[0]
fault.parameters(TF="1.0 [s]", DF="0.12 [s]")        # apply at 1 s, clear 120 ms later

project.build()                                       # Fortran again, before the next run
project.run()
