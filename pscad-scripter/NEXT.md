# pscad-scripter: what is built, and what is left

Written 2026-11-07, after the items on the first version of this list were done. The tool is a
port of `powerfactory-scripter/builder/` to PSCAD, with its engine layer rewritten and its
EMT-specific parts added. `builder/README.md` is the technical README; this file is only the state
of the work.

---

## Built and verified

### The engine layer, live-verified on PSCAD 5.0.0

`builder/runtime/px_core.py`, `px_model.py`, `px_studies.py`, one row per section in
`builder/runtime/API-px.md`. The PSCAD facts the code relies on are in `builder/README.md` §6.

### The Builder

106 blocks in nine categories (17 families, 59 palette entries), six EMT checks of its own, ten
Quick Starts, the AI link adapter and its skill (`ai/`), the guided tour.

### The pages

- `index.html`: the landing page, with the animated hero diagram (the sibling's geometry, retold
  as the frt Quick Start).
- `reference/`: the component reference, an index and one page for each of the 345 Master
  Library definitions with parameters. Generated by `_pages/build.mjs` from
  `reference/components.json` and the curated layer `_pages/definitions.mjs` (`slugOf` there is
  frozen: it makes the page addresses).
- `python/`: the hub and seven guides (`getting-started`, `build-and-run`, `fault-studies`,
  `parameter-sweep`, `harmonics`, `snapshots-and-batch`, `control-tuning`). Each shows the
  Builder's own script for its Quick Start and publishes the full `.py` beside the page. No
  result numbers: there are no recordings from a real case here, so the guides give the method
  and say the values come from the reader's own case.
- `guides/`: the Builder walkthrough, its 18 live demos rebuilt on PSCAD blocks.
- `ai/`: generated by `_ref/agent-doc.mjs` from `builder/agent-notes.md`.

All of them are in `sitemap.xml`; the social cards are `og/pscad-scripter.jpg` and
`og/pscad-scripter-builder.jpg`.

### Fixed while finishing the list

Each was a real fault found by the checks or by reading the generated scripts:

- The Set a fault block and the frt, cct, damping and snapshot Quick Starts named
  `master:tpflt`, which has no timing parameters in PSCAD 5.0.0, so `set_fault` stopped. They
  now name `master:tfaultn` (Timed Fault Logic, `TF` and `DF`).
- cct searched 0 to 100 s (its range was under keys Find limit does not have), passed the
  unstable side (highest speed at least 1.05), and ended the search on the first failed try. It
  now searches 0.05 to 0.5 s, passes at or below 1.05 p.u. and reports a fail.
- `px_run` set the start back to zero after a Start from a snapshot block, so every branch of the
  snapshot Quick Start simulated its start-up again. The snapshot Quick Start also timed its
  fault before the snapshot. Both fixed; `test_snapshot_start.py` covers the first.
- The harmonics spectrum drew as lines and the sweep graph asked for a column called
  `[object Object]`.
- The inspector's "i" linked `reference/master:tpflt/` (a 404; pages go by slug), the download's
  README named the `powerfactory` module, and a few tips spoke of load flows and the Data Manager.
- The shared component tip was over the site's 200-character limit for a tip.
- The tour's built-in demo timed its fault on `master:tpflt` and wired the run's last time from
  a port Frequency nadir does not have; the tour asked for a `headroom` Quick Start PSCAD does not
  have, so it now opens `frt`.
- On an empty canvas the starter card hid the Start block on a short screen (1280 x 720); Fit
  view now keeps Start above the card.
- The component picker's Name field ignored the block's own example (`F1`, `BRK1`).
- Forty-three of the 106 blocks had no icon of their own and fell through to the per-kind
  fallback, so the palette showed the same three glyphs over and over. Every block now has its
  own picture, after PSCAD's own symbols; the fourteen leftover PowerFactory ones that no longer
  mapped to anything are gone. 106 blocks, 106 distinct icons.
- `Component.range()` hands a Choice parameter's symbolic values back as a **set**, with no
  order and no tie to the form's own list of choices, so `pair_choices` has to pair them by
  spelling. It scored a containing match the same as an exact one, so the label "R" took
  whichever of `R`, `RL`, `RC` and `RLC` the set happened to yield first: **24 definitions
  carried wrong values** (`master:Dload` wrote `RLC` for "R"), and the file came out different
  on every run. Exact now beats containing beats a shared opening, over a sorted list, and the
  reference was rebuilt against the engine.
- `components.json` was throwing away the order of the component's own dialog, because the file
  is written with sorted keys. Each parameter now carries `i`, its place in the form, and each
  definition carries `groups`, the order of the form's sections. Both are additive and only in
  `components.json`: `params.json`, which the editor downloads, is unchanged, and
  `_pages/reference.mjs` does not read them yet.

## Left to do

### 1. The home page card

`index.html` at the repo root, and its `home-anim.js` drawing (the `tool-animator` agent draws
those). Only when the user asks for it.

### 2. Two site-wide generators disagree about the AI pages (not this tool's)

`node _ref/og.mjs --tags` adds `og:image:width`, `og:image:height`, `og:image:alt` and
`twitter:image` to every tool's `ai/index.html`, and `node _ref/agent-doc.mjs` writes those pages
without them, so running `--tags` makes `agent-check` A5 fail for every tool. The AI pages were
left as `agent-doc` writes them. The fix belongs in `agent-doc.mjs` (write the four tags) or in
`og.mjs` (skip `ai/`), for the whole site.

### 3. Worth checking on the PSCAD machine

The offline suites cannot settle these. Each needs one live run:

- That a run from a snapshot really resumes at the snapshot's time with the duration added after
  it (the snapshot Quick Start's fault at 2.1 s and its 2 s runs assume so).
- `set_switching` recognises `TO`, `TC`, `T1`, `T2`, `TB` and `Tbrk`, but the Timed Breaker Logic
  (`master:tbreakn`) calls its times `TO1` and `TO2`, so a Set a switching block on it stops with
  "no opening-time parameter". Adding them is a one-line change to verify live.
- The six live block runs and `live_tests.py` after the snapshot fix in `px_run`.

### 4. Site-wide checks failing elsewhere (not this tool's)

On 2026-11-07 `node _ref/abbr-check.mjs` failed once, on `embed/index.html` ("shared layer
present"), and `node _ref/button-check.mjs` once, on `rentvsownhouse/sensitivity/id/` (its Open CSV
button's picture). Neither file is touched by this tool. `tip-check pscad-scripter` passes.

### 5. Not ported, on purpose

- `_ref/share-check.mjs` and `_ref/scenario-check.mjs` drive form tools with scenario presets and
  chart share menus. The Builder has neither (the sibling Builder is not in them either); its
  saved state is the workflow `.json`, which `agent-check` A2 and A4 exercise.
- The sibling's live suites `blocks/pf/` and `templates/run.mjs` drive PowerFactory.
  `blocks/run.mjs` and `templates/build.mjs` are the PSCAD ones.
