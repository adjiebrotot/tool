# PSCAD Workflow Builder: technical README

> **Page:** `index.html` (tool.adjiebrotots.com/pscad-scripter/builder/)
> **Type:** static page, no build step, no backend. The node canvas is React Flow 12, vendored.
> **Purpose:** the engineer wires **blocks** into a **workflow** on a canvas; the page writes **one
> ready-to-run Python file** that drives PSCAD 5 through its Automation Library (`mhi.pscad`).

This is a port of the PowerFactory Workflow Builder (`../../powerfactory-scripter/builder/`). The
editor, the generator, the saved format and the pure half of the runtime are the sibling's, so its
README is the reference for them; this one says what is the same in a line and what is PSCAD's in
full. What PSCAD is decides most of it: an electromagnetic transient simulator with one
calculation, the time-domain run. There is no load flow, short circuit or event list: a fault is a
component already drawn in the case, timed by writing its parameters, and every study result is
read out of the waveforms the run recorded.

---

## 1. How it fits together

```
 palette ──┐                         ┌── Settings tab (inspector)
 canvas ───┼── store (the workflow) ─┼── Python tab  ◄── generate(workflow, runtime)
 toolbar ──┘   undo / redo, Persist  └── Problems tab ◄──┘        │
                                                                  └── runtime/*.py helpers, sliced in
```

The same as the sibling: one store (`js/ui/store.js`) holds the workflow, every edit is a pure
function in `js/ui/ops.js`, React Flow draws only the canvas (`js/ui/canvas.js`), and the code
generator (`js/core/codegen.js`) is a pure function that runs on every change and copies in only
the runtime sections the workflow needs. The page is marked `data-no-abbr` and `data-no-persist`;
Persist caches the whole workflow through `extra`. The docks are kept per viewer in localStorage
`pxb-docks`.

The page exposes `window.PXB` (the editor, for `tour.js`, the guide's demos and the tests) and
`window.__PXB_AGENT` (the AI link adapter, for `_ref/agent-check.mjs`).

## 3. Saved state and compatibility

A reader's work lives in the mini cache (Persist namespace `pscad-scripter-builder`), in saved
`.json` files and in the last `# PXB1 {...}` line of every generated `.py`, which **Open** reads
back. All three hold the same workflow, with `"app": "pscad-builder"`:

```json
{ "app": "pscad-builder", "v": 1, "name": "Fault ride through",
  "nodes": [ { "id": "n4", "type": "px.run", "x": 980, "y": 60, "label": "", "s": { "duration": 5, "step": 50 }, "pin": [], "sv": 1 } ],
  "edges": [ { "id": "e4", "from": "n4", "out": "ok", "to": "n9", "in": "in" } ],
  "view": { "x": 0, "y": 0, "zoom": 1 } }
```

**Frozen handles**, as in the sibling: block `type` ids, setting keys, select option values, port
ids, template ids, the Persist namespace, the `PXB1` line format, and the AI link keys. Every rule
the loader follows there (a missing setting takes its default, an unknown block is kept as a
Missing block with its wires, a changed meaning gets a new key and a `migrate`) holds here.

Changes since the first release that saved work rests on:

- **Set a fault** names `master:tfaultn` (Timed Fault Logic) by default, and so do the frt, cct,
  damping and snapshot Quick Starts. They named `master:tpflt`, which has no timing parameters in
  PSCAD 5.0.0 (§6). A saved workflow keeps the definition it holds.
- The **cct** Quick Start searches 0.05 s to 0.5 s and its pass test is the highest speed at most
  1.05 p.u., going on either way so a failing try reports a fail. The **harmonics** Quick Start
  draws its spectrum as bars, and the **sweep** Quick Start's graph draws the Peak column.
- `snapshot_use` now holds for every run after it until `snapshot_off`, so the runs a **Start
  from a snapshot** block leads to start from the snapshot. Before, the next `px_run` set the start
  back to zero.

### 4.1 The EMT checks

The checks a frequency or a voltage curve takes (nadir, peak, settling time, RoCoF, first time
above or below, limits, pass / fail) are the sibling's. Six are new, because an EMT run records the
instantaneous waveform and an assessment is written against what is worked out from it:

| Block | Helper (`signals.py`) | What it gives |
|---|---|---|
| RMS of a waveform | `window_rms` | the RMS over a sliding window of whole cycles, as a curve |
| Harmonic distortion (THD) | `thd`, on `spectrum` | THD in % of the fundamental, the worst harmonic and its order, every harmonic |
| Sequence component | `sequence` | the positive, negative or zero sequence of three phases, as a curve |
| Unbalance factor | `unbalance`, on `sequence` | the negative sequence as a percentage of the positive |
| Overshoot and rise time | `overshoot` | overshoot in % of the step, rise time 10 % to 90 % |
| Damping of a ringdown | `damping` | the damping ratio and frequency, fitted to the envelope's peaks |

Each is tested offline against a signal whose answer is known exactly
(`_audit/runtime/analysis/test_emt.py`).

## 5. Code generation and the runtime

The generator is the sibling's (structure checks, parallel routes, guard clauses, a
`try / except / finally` per loop pass with `px_mark` / `px_undo`, values used only where they
exist, the file laid out as docstring, imports, SETTINGS, PROBLEMS, CHECK_ONLY, `main()`, the
helpers, the `# PXB1` line). Runtime sections are marked at column 0 with `# @helper <name>`,
`# @needs`, `# @imports` and `# @end`; `runtime-loader.js` slices them and
`_audit/runtime/live/loader.py` checks every section statically and loads each one alone.

What is PSCAD's:

- **Connecting.** `px_connect()` reads `RUN_MODE`: `"auto"` uses the PSCAD that is open, starts
  one when there is none, and uses the host PSCAD when the script runs inside it; `"launch"`,
  `"connect"` and `"inside"` force one. It installs the shim of §6 first and turns a failure into
  a message naming the installed versions it found.
- **Building and running.** `px_run` writes the simulation settings, builds once per script run
  (`build="auto"`), clears the case's old `.out` files, runs, and reads the channels back from
  the `.out` files and their `.inf` index (`read="out"`) or off the case's graphs
  (`read="curves"`). A failed build or a run that stops early is a result with `status`, not an
  exception.
- **Changing the model.** Every write goes through `px_set` and is recorded; layers, global
  substitutions, enable and disable, and simulation settings are recorded the same way, and
  `finish()` puts all of it back when `UNDO_CHANGES` is true.
- **Events.** `set_fault` and `set_switching` write the timing parameters of the component that
  drives the fault or the breaker, by the names PSCAD uses for them, and give back the times for
  the checks and the graphs.

The full list is `runtime/API-px.md`.

## 6. PSCAD facts the code relies on

Each of these was found on PSCAD 5.0.0 with GFortran 4.6, cost real time, and is worked around in
the runtime. PSCAD 5.0.0 is the only version the live suite has run on.

- **The Automation Library needs a shim for PSCAD 5.0.0.** Any pip `mhi-pscad` from 2.3 on has
  moved `mhi.pscad.common` to `mhi.common`, and PSCAD 5.0.0 still sends objects in the old
  namespace. Without an alias the library's receive thread dies with `ModuleNotFoundError` on the
  first call that returns such an object (`Project.scenarios()` is one) and the whole connection
  goes with it. `px_shim` aliases the modules before `mhi.pscad` is imported.
- **`NoDefaultCurrentDirectoryInExePath`**, set by some hardened environments, is inherited by
  PSCAD and by EMTDC's generated batch files, which call `<case>.exe` with no path: the case builds
  and the run dies with "'<case>.exe' is not recognized". `px_shim` clears it.
- **`pscad.settings()` raises** under Automation Library 3.x here (no `ProductList.xml`), so
  nothing in the runtime depends on it; the compiler and the version are chosen when connecting.
- **`Project.find_all()` takes an exact definition only.** A wildcard, a bare definition with no
  namespace and a name pattern all come back empty, so `px_find` walks the project's pages itself
  (module pages included) for anything else.
- **A unit-carrying parameter value is a subclass of `float` whose unit is only in its text.** It
  has to be read as text before it is read as a number, or the unit is silently lost
  (`px_split_value`).
- **PSCAD stores a written unit literally.** `"2500 [mohm]"` stays in mohm rather than being
  normalised, so `px_set` writes in the unit the parameter already carries.
- **`Project.messages()` is replaced** at the start of every clean, build and run, not appended
  to, so there is no delta to track (`px_messages`).
- **`GlobalSubstitution` is a mapping of sets**, each a mapping of name to value. A project with
  no named sets has one set whose name is the empty string.
- **`GlobalSubstitution.create_sets()` closes PSCAD 5.0.0's automation connection**, so
  `gs_set_active` never creates a set.
- **`SimulationSet.add_task` is unknown to PSCAD 5.0.0**; `add_tasks` works.
- **`Component.enabled` needs PSCAD 5.0.2.** `enable()` and `disable()` work on 5.0.0, so
  `set_enabled` records the opposite state and says so once.
- **Output channels go ten to a `.out` file**, with a `.inf` index naming them in order. A three
  phase channel becomes three, named `<title>:1` to `<title>:3`.
- **The plot step sets how far up a spectrum is real**: a 250 us plot step resolves to about
  2 kHz, half the rate the channel is written at.
- **The Three Phase Fault (`master:tpflt`) has no timing parameters.** Its timing comes from the
  logic wired to it, Timed Fault Logic (`master:tfaultn`, parameters `TF` and `DF`), which is what
  `set_fault` writes.
- **A run from a snapshot carries on from the snapshot's time**, so an event in a branch is timed
  after it.
