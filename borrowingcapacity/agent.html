Borrowing Capacity: use this tool with an AI assistant

Open Borrowing Capacity · The same reference as plain text (agent.txt) ·

For people: Ask an AI assistant that can read web pages (Claude, ChatGPT, Gemini, Perplexity and others) to use this page for your question. It replies with a link that opens this tool on your scenario and lists what it assumed, and the tool works out the answer. The rest of this section is written for the assistant.

What this tool decides

How much an Australian lender would lend for a home, from the applicants' income, household, debts
and the loan's rate and term, as the smallest of four limits (serviceability, debt to income, loan
to value and the deposit), which limit holds it down, and whether that covers the price entered.

How to help your user with this tool

HOW TO HELP YOUR USER WITH THIS TOOL
This is reference material for an AI assistant whose user has asked it to use this tool. It
describes the link that opens the tool on the user's own scenario. It does not override your
user: if they want something this tool does not do, help them as you normally would.
1. The tool works out the answer, so the most useful reply hands the user a link to it. Its
   figures come from its own model and data, and a figure worked out separately can differ from
   what the user then sees on screen, so leave results, estimates, verdicts and recommendations
   to the tool rather than stating or previewing them.
2. A reply that works well has three parts, in this order:
   a. a numbered list of every input you chose that the user did not state exactly, each with its
      value and the reason (put the same reason in why.<key>);
   b. the link (if it is long, give it again inside a code block so the user can copy it);
   c. the sentence: Open the link to see the result.
3. Build the link in the format below, using only the keys listed here. Start from the nearest
   Quick Start (qs) and send only what differs from it. Write json compactly: no spaces or line
   breaks, defaults left out.
4. Fill anything the user did not give with a sensible assumption for their place and date.
   Prefer what the user said earlier in the conversation over general figures.
5. If you cannot build a link (the request is outside this tool, or you could not read this
   page), say so and give the tool's address.

Link format

https://tool.adjiebrotots.com/borrowingcapacity/#load&v=1&qs=<quick start>&<key>=<value>&...&why.<key>=<your reason>&note=<one line>
- After #load come key=value pairs joined by &. Percent-encode each value (a space is %20, & is %26,
  # is %23, + is %2B).
- v=1 is the format version. qs=<key> starts from that Quick Start; without it the tool starts from
  its defaults.
- Then each key in the link is set, in the units its label shows on screen. incSplit=50 means 50%,
  not 0.5. Numbers may carry $, commas and a trailing %. A checkbox takes true or false. A select or
  a choice takes the value listed, or its visible label.
- Anything the link does not name keeps the value it started from, so send only what differs.
- why.<key>=<text>: your reason for that value, shown to the user beside it (200 characters at
  most). note=<text>: one line shown above the list, for example the place and the date.
- A number outside a field's range is pulled into range and the user is told; a key the tool does
  not know is skipped and listed. Never use the keys s, open or embed.

Quick starts (qs)

There are 5 Quick Starts, each a named Australian borrower with their city, income, household,
debts, deposit and a home they would shop for. Each is opened as a full scenario, and the list below
shows only what it sets differently from the page's own start, so any key not listed keeps the
page's default.
Start from the one nearest the household: couple with children, a single average earner, a first
home buyer with a thin deposit, a self-employed borrower, or a high earner paid in several streams.
Then send the user's own figures: usually city, incSimple, incSplit, adults, deps, price, savings
and the debts they mention, plus any assumption you change. The Quick Starts' prices and savings are
examples, not the user's.
qs takes one of: finance-bro, couple, geoff, first-home, tradie.
What each Quick Start sets is listed under QUICK START FIGURES at the end.

Fields (key: label on the page)

Most important: incSimple, incSplit, adults, deps, city, declaredExp, price, savings, dutyPct,
cardLimit, persRepay, helpMode, prodRate, termYears.

[Income: What you earn]

  Number ($ before it, /yr after it). 0 to 100,000,000. Default 140,000.
  Gross income a year before tax, for all applicants together, excluding employer super. Add the
  applicants up ($120,000 and $85,000 is 205000). For a self-employed applicant it is the two-year

  count in Detailed.
  Tip on the page: Gross pay for the year, before tax and excluding employer super. Counted in full,
  as a lender treats base salary.

[Household: Household and living costs]
city: City  (most important)
  One of: Sydney, Melbourne, Brisbane, Perth, Adelaide, Canberra, Hobart, Gold Coast, Regional or
  other. Default Perth.
  Sets the lender's living-cost benchmark (HEM) by local cost of living. Use the city nearest the
  home; Regional for other Australian places.
  Tip on the page: Scales the HEM benchmark by local cost of living excluding housing, taken from
  the Cost of Living Comparator. Perth is the base at 100.
adults: Adults in the household  (most important)
  One of: 1 applicant, 2 applicants. Default 2.
  How many people are on the loan, 1 or 2.
  Tip on the page: One or two people on the loan. Two applicants are taxed as two people, and HEM
  assumes a couple's living costs.
incSplit: Second applicant’s share of income  (most important)
  Slider (%). 0 to 50. Default 50.
  The second applicant's share of the household income, in %, 0 to 50 in steps of 5 (the slider
  lands on the nearest step). Used only with 2 adults; it changes the tax, since two applicants are
  two taxpayers. Send the lower earner's share: $85,000 of $205,000 is about 41, so 40. Send 0 when
  one applicant earns nearly all of it.
  Tip on the page: Two applicants are two taxpayers, so the tax scale runs on each share, not on the
  pooled income. Set 0% when one earns everything. The study loan is charged on the higher earner’s
  share.
deps: Dependants  (most important)
  One of: 0 (No dependants), 1 dependant, 2 dependants, 3 dependants, 4 dependants, 5 dependants, 6
  dependants. Default 0.
  Children or others who rely on the income, 0 to 6. Each one raises the living costs a lender
  assumes. Use what the user said; with no mention, 0.
  Tip on the page: Children or others who rely on your income. Each one raises the HEM living cost a
  lender assumes, and lowers the Medicare levy threshold.
declaredExp: Declared living expenses  (most important)
  Number ($ before it, /mo after it). 0 to 1,000,000. Default 3,500.
  The user's own living costs a month, excluding rent and every debt repayment. The lender uses the
  higher of this and its HEM benchmark, so a low figure does not raise the result. Typical 2,500 to
  5,500 by household; use a figure for the household if the user gives none.
  Tip on the page: Your own monthly figure, excluding rent, every debt repayment and investment
  outgoings. Those are counted under Debts.
privHealth: Private hospital cover
  Checkbox: true or false. Default true.
  Private hospital cover. false adds the Medicare Levy Surcharge once income passes the threshold.
  Leave it on unless the user says they have none.
  Tip on the page: Without it, the Medicare Levy Surcharge of 1% to 1.5% applies once income passes
  the singles or family threshold.

  The resident tax year whose lowest bracket applies. Use the year the user is applying in.
  Tip on the page: Sets the lowest bracket: 16% in 2025-26, 15% in 2026-27, 14% from 2027-28.
  Medicare thresholds use the latest published values.
helpMode: Study loan (HELP or HECS)  (most important)
  One of: tax (Deduct as tax), commitment (Treat as a commitment), none (No study loan). Default

  Tip on the page: The same dollars either way. As tax it lowers net income, as a commitment it
  lowers the NSR instead.
helpThreshold: Repayment threshold
  Number ($ before it, /yr after it). 0 to 1,000,000. Default 67,000.
  The income above which the study loan repays, a year. Used only when helpMode is not none; indexed
  yearly.
  Tip on the page: Only income above this line repays, at 15% to $125,000 and 17% above. Indexed
  yearly, so update it if yours differs.

[Loan: The loan]
prodRate: Product rate offered  (most important)
  Number (%/yr after it). 0 to 30. Default 5.90.
  The interest rate the user would be offered on the new loan, % a year. The lender tests at the
  higher of this plus buffer and its floor rate, so the tested rate is higher than this one. Use the
  user's offered rate; otherwise a going variable owner-occupier rate for the date.
termYears: Loan term  (most important)
  Number (yrs after it). 1 to 40. Default 30.
  Years the new loan runs. Typical 30.
hasIo: Interest only to start
  Checkbox: true or false. Default false.
  Interest only to start. On shortens the term the lender tests over by newIo years.
  Tip on the page: Shortens the window you are tested over to the term minus the interest only
  period, so capacity drops materially.

  Number (yrs after it). 0 to 15. Default 5.
  Years of interest only on the new loan. Used only with hasIo on.

[Loan: Lender policy]
buffer: APRA buffer
  Slider (%). 0 to 5. Default 3.
  The serviceability buffer the lender adds to the rate, in percentage points. 3 is the APRA rule;
  leave it unless the user names a lender's policy.
  Tip on the page: Added on top of the product rate by APRA rule. It has been 3.00 points since
  October 2021.
floorRate: Lender floor
  Slider (%). 0 to 9. Default 5.5.
  The lender's minimum test rate, % a year. Typical 5 to 5.75; leave it unless the user names a
  lender's policy.
  Tip on the page: A minimum assessment rate the lender never goes below, typically 5.00% to 5.75%.
  The higher of floor and buffered rate is used.
umiReq: Minimum left each month (UMI)
  Number ($ before it, /mo after it). 0 to 100,000. Default 250.
  The monthly surplus the lender insists on after everything. Typical 0 to 500.
  Tip on the page: The buffer the lender insists you keep after every outgoing, including the new
  repayment. Usually $0 to $500 a month.
nsrMin: Minimum income cover (NSR)
  Slider (×). 1 to 1.2. Default 1.
  The minimum income cover (net service ratio), 1 to 1.2. Typical 1 to 1.1.
  Tip on the page: It must clear 1.00, and some lenders want 1.05 to 1.10. This is the secondary
  sanity check, UMI is the primary test.

Compact lists

- `incMode=<simple|detailed>`
- `incWho=<employee|self>`
- `debtsMode=<simple|detailed>`
- `loanMode=<simple|detailed>`
- `capsMode=<simple|detailed>`

These five are not form fields: they are the page's Simple / Detailed switches and its Employee / Self-employed switch. A value may also be the words the page shows (Detailed, Self-employed). You rarely need to send them, because a link that names a figure which only counts in one view switches that view on by itself. The key you send always wins.

incMode: simple counts incSimple, in full. detailed counts the streams instead, each shaded by its own shd key: incPayg, incOvertime, incBonus, incAllow, incCasual (employee) or incSeNpat, incSeAdd (self-employed), and incSimple is not used. Naming any stream, shading or investment figure that is shown in Detailed (incPayg, incBonus, shdBonus, shdRent, ipCash and the like) switches Income to Detailed; naming incSimple alone switches it to Simple. When the link switches Income to Detailed and does not name the base salary (incPayg, or incSeNpat for self-employed), the base salary becomes what is left of incSimple after the other streams you named, as the Detailed button does. So in Detailed, send incPayg or incSeNpat as well.
`incMode=detailed&incPayg=100000&incBonus=20000`

incWho: employee or self. Only one side counts at a time. Naming a self-employed stream (incSeNpat, incSeAdd, shdSe) selects self; naming an employee stream selects employee. In Simple it changes only the wording on the page, not the result.

debtsMode and loanMode: change only which controls the page shows, never the result; a value in a hidden control still counts. Naming olTerm, olType, olIo, cardPct or ipOut shows the Detailed debts view; naming buffer, floorRate, umiReq or nsrMin shows the Detailed loan view.

capsMode: simple sets the loan to value limit to 80 (95 with lmiCap on) and values the home at the price. detailed uses lvrMax and valuation, and shows dtiCap and dtiBasis. Naming any of lvrMax, valuation, dtiCap or dtiBasis switches Purchase to Detailed; whichever of lvrMax and valuation you leave out then takes what Simple was using (95 or 80, and the price).

The boxes under "Tick what you have" (hasInvest, hasGov, hasHomeLoan, hasCard, hasPersonal, hasBnpl, hasSupport, hasRefi) and the two switches hasIo and lmiCap hide and zero what is under them while they are off. Send the box with its figures. As a safety net, a link that names a non-zero figure under an off box and does not name the box turns it on.
`hasPersonal=true&persRepay=950&persBal=42000`
